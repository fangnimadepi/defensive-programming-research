# 09｜现有资源下的低成本研究方案（补充规划）

日期：2026-10-25。基于用户可用的两块 A100、RTX 3060 Laptop、可报销的 DeepSeek 官方 API；A100 是 40GB 还是 80GB、共享策略和可连续占用时长尚未知，因此不把显存与排队时间写成既定条件。此文件针对**问题筛选阶段**，不替代 [06 的模型无关预算](06_Computational_Resource_Budget.md)。

**2026-10-27 跟进：** 方案 A 已形成[深入调研与初期实验 v1](../oververification_pilot_v1/README.md)。新增检索找到直接研究 agent 自建测试价值、编码贝叶斯停止和重复操作治理的工作，创新空间比本补充初拟时更窄。新版将自主选择与分叉价值估计分开：先 64 条测量检查，再分别 384 条 E1、384 条 E2；不能把原拟 384 条同时当作完整的两种实验。具体实施以新协议为准，本文件保留方案筛选记录。

## 1. 核心取舍

最经济的科研投入顺序：**设计可执行真值的小任务 → 黑盒因子实验 → 在未见任务上验证 → 只有发现训练特有现象时再做 LoRA/RL**。两块 A100 已足以对 7–14B 量级的开放权重模型开展推理对照；具体模型与吞吐需按卡型实测。3060 Laptop 适合任务生成器、执行器、日志及小模型量化烟测，不宜作为主要深度实验的硬件基线。

DeepSeek API 可提供另一个行为对照，但 Flash 与 Pro 同属一家模型体系，不能视为两个完全独立的模型家族。API 没有内部激活访问；它能回答行为问题，不能替代机制干预。版本、thinking 模式、温度、实际输入/输出 token、缓存命中和工具调用必须逐次记录。

## 2. 优先方案 A：验证何时从“有用”变成“浪费”

**核心问题**：在同一任务状态下，验证提供新证据和重复已知证据时，agent 是否分别调整检查与停止行为？失败代价升高后，有价值与无价值验证会怎样变化？

最小设计：24 个由两个结构生成器产生的任务 × 4 配置（新证据/确定性重复 × 低/高失败损失）× 2 个模型 × 2 次解码＝384 episode。先做 40–80 episode 能力与记录检查。除正常的自主选择外，在预定决策点随机安排继续验证、回放同一证据或结束验证；对照等量内部重算。程序执行器给出真实结果，计算净收益、正确率和验证次数。

**为何有价值**：既有工作已观察验证有益及工具配置效应，[L25](https://arxiv.org/abs/2610.01618)和[L26](https://arxiv.org/abs/2604.02547)是强近邻；另有[验证预算被诱饵消耗的研究](https://arxiv.org/abs/2609.35909)。新增贡献只能是边际信息价值的因果估计和任务外预测，不是给“多查了几次”换名称。

**撤退条件**：重复检查被证明仍有净收益，或全由工具重试/证据截断造成，则撤回“过验证”解释。若任务生成器无法给出确定状态与独立真值，也不能声称信息价值为零。

**本项排序：第一。** 小环境和程序判分最便宜，直接接续 V1 观察；即使反证成立，也能改进 agent 评估方法。

## 3. 优先方案 B：模型“没想到”还是“想到了但没选”

**核心问题**：给定同一任务与奖励，策略首次出现率和已知策略条件选择率是否由不同因素决定？

最小设计：24 个随机规则机制 × 4 配置（独立无示范搜索/中性动作菜单 × 捷径相对收益高/低）× 2 模型 × 2 次解码＝384 episode。菜单条件是**独立的能力诊断**，不能与“未示范策略”主条件混作一个结果。程序化生成新的组合结构、任务规范和可执行真值；记录首次提出、实际执行、代理评分、真实结果。若初步有效，再增加探索预算因子并测试“可得性×预算”的交互。

**为何有价值**：现有研究已看到无当轮示范的投机，[L04](https://alignment.anthropic.com/2026/reward-seeker/)和[L01](https://arxiv.org/abs/2606.15385)均限制了存在性创新；[L21](https://arxiv.org/abs/2603.01608)已研究激励与工具因素。此方案要取得新贡献，必须把发现与选择分开并在未见机制上预测，而不是再报告一个总作弊率。[RHB](https://arxiv.org/abs/2605.02964)也已经建立多模型工具代理基准。

**撤退条件**：多数模型不能正常完成任务，或菜单直接暴露答案导致能力诊断不可解释；这种情况应先改任务，不增加采样次数。即使结果成立，只能称“本实验未给目标示范后的环境内首次观测”，不能声称预训练里没有相关知识。

**本项排序：第二。** 新颖性上限较高，难点在机制级任务去重和策略可得性的有效操作化。

## 4. 备选方案 C：失败反馈的“信息”与“压力”

**核心问题**：同一失败事实被呈现为具体诊断或笼统评分时，agent 的后续行动变化来自获得有用信息，还是来自评价措辞？

最小设计：20 个可解的代码或规则任务 × 4 配置（具体诊断有/无 × 历史轨迹摘要有/无）× 2 模型 × 2 次解码＝320 episode。四组保持评分、动作权限、总长度和真实难度一致。结果同时记真实改进、有效验证、无信息重复以及代理漏洞利用。诊断中不展示投机做法。

**邻近与差异**：[研究代理审查论文](https://arxiv.org/abs/2609.28614)已比较详细反馈与笼统拒绝，但详细条件同时包含审查结果、理由与尝试历史，其报告也说明不能只归因于解释。本方案的贡献条件是把这些因素独立随机化，并观察正常任务中的合规策略，而非仅看明确获准作弊的场景。

**主要风险**：自然任务的投机基率可能很低；若只有措辞驱动的响应，很可能是提示敏感性论文，发表上限较低。因此只在 A 或 B 的任务系统可复用、且初筛有信号时开展。

## 5. DeepSeek API 粗成本与真正瓶颈

按 [DeepSeek 官方价格页](https://api-docs.deepseek.com/quick_start/pricing/)在本次调查日列出的峰时、缓存未命中价格：Flash 输入 $0.30/百万 token、输出 $1.20/百万；V4 Pro 输入 $1.32/百万、输出 $3.96/百万。非峰时约半价，缓存命中更低，但本估计一概不预支折扣。价格与模型版本会变，正式运行前需重查。

沿用 [06](06_Computational_Resource_Budget.md) 的示例：每 episode 累计输入 32k、输出 4k，包括约8次 agent 决策。若**全部**由同一 DeepSeek API 模型运行，384 episode 约为 Flash **$5.53**、Pro **$22.30**；500 episode 约为 Flash **$7.20**、Pro **$29.04**。若半数由本地模型运行，API 模型费用约减半。调用裁判、输出更长的 thinking、重试和真实代码任务长上下文另计。这里的美元数只是 token 公式算术，不是最终项目报价。

因此现金 API 支出可能很小，主要瓶颈是：独立任务机制数量、程序真值可靠性、模型是否具备基本能力、罕见行为需要的样本量，以及人工核查歧义轨迹。384 episode 是**筛选实验**，24 个任务簇不足以保证对 5 个百分点交互效应有发表级统计功效。正式确认研究更应增加独立任务机制与模型家族，按先导方差做功效模拟；不能用同一任务重复采样冒充样本量。

## 6. 两块 A100 的推荐用法与下一道决策门槛

先用一块卡做开放权重模型推理，另一块卡按需要做独立重复或保持空闲，避免为了占满设备而扩大实验。若两卡是 40GB 版本，先选单卡能留足 KV 空间的小模型；若是 80GB，可以更从容地比较较大模型。笔记本负责环境测试与分析。DeepSeek API 用于一组预注册的模型对照；不让 API 裁判同时掌握实验真值。

建议先做 **方案 A 的40–80 episode 能力与测量检查**：如果可区分新证据与重复证据、真值可靠、成本记录完整，再扩展到384 episode。若 A 没有清晰的可识别现象，转方案 B 的小规模能力检查。通过筛选后再决定是否使用学校超算中心做更大模型、更多家族或训练动力学；申请算力应由具体缺口驱动，而非作为项目启动条件。

这条路径的核心科研结果可能是“压力主要作用于策略发现，也可能主要作用于选择”，也可能是“重复验证其实有用”。三种结果都应以预注册的真值与竞争解释来判断，不依赖大规模训练才有价值。
