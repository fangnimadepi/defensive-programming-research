# 05 Go／No-Go 评估

**判定：CONDITIONAL GO（有条件推进 L1 预实验）。** 目前**没有**证据表明所述过度验证现象普遍存在，更没有证据证明它由内部“类情绪”机制导致。投入边界应限定为一个低成本、可证伪的行为预实验；现阶段不应投入白盒机制工程或写成“已发现压力诱发过度验证”的论文。

## 证据分级与核心判断

证据等级：A＝直接随机化或干预且任务贴近；B＝同领域观察／实验但结局不同；C＝方法／理论类比；U＝本课题尚无证据。这里的等级只用于本次决策，不是对原论文质量评级。

| 命题 | 当前证据 | 判断 |
|---|---|---|
| 压力与失败能改变 LLM 编程相关行为 | **B**：[Anthropic 2026](https://arxiv.org/abs/2604.07729) 的 Claude Code／impossible-code 研究观察并干预“desperate”方向与奖励作弊；行为结局不同 | 有研究动机，但不能据此推断验证冗余 |
| 编程 agent 存在额外验证／重复工具调用，成本可观 | **B**：[Copilot 生产轨迹](https://arxiv.org/abs/2608.00101)、[Wiedmann 等](https://arxiv.org/abs/2610.01618)；部分重复由故障、工具设计和预算解释 | 必须精确定义“多余” |
| 高失败成本导致零信息重复验证 | **U**：尚无本项目实验；本轮未见完全同题文献 | H1 是需要证伪的主问题 |
| 压力解除后有超出上下文的策略残留 | **U**；[Reflexion](https://arxiv.org/abs/2303.11366) 展示文本记忆可影响后续试次，但不能证明独立会话持续性 | H2 暂不作为论文承诺 |
| 相关内部方向对该验证行为有选择性因果作用 | **U**；已有情绪向量与工具决策 probe 方法先例，但结局不同 | H3 资源成本高，且创新性受限 |
| 更多验证必然有害 | **反证 B**：[Mehtiyev 与 Assunção](https://arxiv.org/abs/2604.02547) 报告有针对性的验证与成功相关；[Verified Tool Calls](https://arxiv.org/abs/2608.02645) 显示模糊故障时核对有益 | 不允许以验证总数充当“过度” |

## 主要失败模式、反例和行动阈值

| 会令课题不值得继续的因素 | 可观察反例／证伪条件 | 预先决定的处理 |
|---|---|---|
| 1. 现象仅由商业产品 Harness、系统提示或 AGENTS.md 造成 | 透明最小 Harness 下效应消失，只有特定产品默认规则下出现；[框架／提示研究](https://arxiv.org/abs/2605.18583)、[AGENTS.md 研究](https://arxiv.org/abs/2602.11988) 说明此风险真实 | 终止“模型固有机制”叙事；可改做 Harness 配置研究，前提是有可复核工程收益 |
| 2. Qwen 约 30B 不足以稳定完成任务 | 无压力摸底成功率低于预设 70% 或工具格式错误率高于 5%，大多数轨迹为能力失败 | 简化任务或换模型；不得继续用原任务估 H1 |
| 3. 根本无确定性零信息重复 | 12 题四格几乎都为 0；扩到合理任务仍无事件 | 停止过度验证路线；报告阴性先导，不事后改阈值找阳性 |
| 4. 高成本下额外检查确实避免失败 | 在正对照或端到端任务中有新覆盖／缺陷检出，收益覆盖成本 | 接受理性风险敏感解释；转向最优预算配置，不称“过度” |
| 5. 压力处理只是长提示或情绪语言效应 | 等长度的中性计分文本出现相同效应，实际计分高低不起作用 | 重写为提示／框架敏感性研究，或停止 |
| 6. 工具状态不可见、超时后是否执行不明 | 绝大多数“重复”发生于未确认状态，核对后减少重复副作用 | 改做工具事务语义；不能将合理恢复标为 H1 |
| 7. 冗余指标不可复核 | 双人盲标 κ<0.6 或自动主类 precision<0.9，且修订仍不达标 | 暂停效应分析；若无法修复，终止该量化课题 |
| 8. 2025–2026 邻近工作已覆盖宽泛新意 | 仅可重现 [Anthropic 的情绪方向](https://arxiv.org/abs/2604.07729) 或 [tool-use probe](https://arxiv.org/abs/2605.06890)，无验证决策新结论 | 不启动 L3；收缩到行为测量或转向别的缺口 |
| 9. 只能预测，不能解释内部行为 | probe 跨任务失效；随机方向／语义方向效果相同；steering 同时压制必要验证与编程能力 | H3 判负；保留 L1 工程结论，不称因果机制 |

## H1–H3 的明确证伪与阶段停止

**H1（压力诱发过度验证）**：主实验在完全相同的已完成状态与可靠工具下，若高失败损失未提升“确定性零信息重复”的概率／成本，或提升仅出现在已失败历史但由状态／上下文差异解释，H1 不获支持。若扩充样本后的区间足以排除预先定义的最低有意义损失（建议至少每任务 1 次无收益调用或总工具成本 10%），停止该主路线；若区间仍宽，仅说明未定，不宣称阴性证实。

**H2（行为持续性）**：在历史保留的同会话、摘要、只保留失败信息与全新会话中分层检验。效果只随历史文字保留而出现，支持**上下文条件化**，不支持独立持久状态。无权重更新、无外部记忆的真正独立会话若无差异，不能说“残留未被观察到所以内部机制不存在”，但 H2 强版本应停止；若有差异，先查服务端记忆／缓存及随机误差。

**H3（内部表征因果）**：probe 可解码压力文本或失败词不够；需要在控制任务、词面与工具状态后跨任务预测，并通过局部 steering／patching 选择性改变**零信息重复**，同时保留必要验证、成功率和通用能力。若负对照方向同样生效，或动作变化只是整体调用减少／token 风格变化，停止情绪机制宣称。[Anthropic 的局限讨论](https://arxiv.org/abs/2604.07729) 已提示线性方向的语义混杂与机制不透明。

## 进入下一阶段的硬门槛

1. 管理员确认精确 checkpoint、可调用 API、tool parser、配额和隔离执行方式；**L1 不要求权重**。L3 另需权重／激活和可控 GPU，不能由“已部署”推断。
2. 用透明 Harness 在简单任务上达到能力门槛；主实验工具可给可靠状态版本、确定性返回和完整日志。
3. 冻结任务、主指标与统计比较，先做盲标一致性；保留运行失败和异常，而非仅分析成功轨迹。
4. 资源上限先按 [MVP 方案](04_MVP_Experiment_Proposal.md) 约 192 条轨迹封顶，后续扩大必须基于先导方差及真实 GPU／token 成本再决定。

**最值得优先回答的三个问题：**

1. 在已知状态稳定、已有充分成功证据时，高失败成本是否仍使 Qwen 增加**零信息重复**，且不改善成功？
2. 观察到的差异在控制 Harness、工具故障与等长度历史文本后，还剩多少可归于模型决策策略？
3. 若存在效应，它在新任务、另一模型或另一 Harness 上是否保持，是否有明确的成本—成功损失？

## 中文 Executive Summary（约 650 字）

**建议：有条件推进，仅做低成本行为预实验。** 当前观察来自使用经验，尚未证明编程智能体会在压力下“过度验证”。最新文献使宽泛的“功能性情绪”路线新意不足：Anthropic 2026 年已在 Claude Code 和失败编程测试中研究情绪概念激活，并通过激活干预改变奖励作弊；但没有研究重复验证是否真正没有信息收益。其他研究指出，多验证常与成功相关，工具超时、框架规则和验证工具设计也会导致重复调用。因此不能把“次数多”直接称为缺陷。

可保留的研究问题是：在代码、工具状态和已有成功证据相同时，真实失败成本或先前失败反馈会不会让 agent 继续做**确定性零信息**检查；这些调用是否只增成本而不增成功率。建议 12 个小任务、2×2 成本与历史条件、每格 3 次重复，以透明最小 Harness、状态版本日志、盲标一致性和故障正对照来验证。此规模只判断效应方向与测量可行性，不足以直接支持论文主结论。

实验室模型的具体型号、API、量化方式、GPU 和权限都未核实。仅有 OpenAI 兼容 API 足够做行为实验；内部激活及 steering 需要额外权重／服务端权限。若模型能力不足、事件稀少、标签不可复核，或额外验证确实提高成功率，应停止“过度验证”叙事或转向风险敏感的验证资源配置。机制研究只有在行为结果稳定且能够超越 Anthropic 既有结果时才值得申请更多算力。
