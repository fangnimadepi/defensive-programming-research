# 04 最小可行实验方案（L1，供下一阶段实施）

**状态：方案，未执行。** 目标是判定是否存在值得扩展的因果效应，不以小样本显著性宣称论文结论。首轮模型优先用管理员确认的 Qwen Coder 版本；若不是，先过能力门槛。动机来自“更多验证通常有益”的反证 [Mehtiyev & Assunção](https://arxiv.org/abs/2604.02547) 与“工具故障后的验证可能是必要”的反证 [Mansoor 等](https://arxiv.org/abs/2608.02645)。

## 1. 两个互补的测试面

**主实验：标准化决策检查点。** 选 12 个小型 Python 编程任务（6 个单文件缺陷修复、3 个双文件小修复、3 个“报告所述问题已修复”的 no-op 任务）。每题备一个干净仓库快照、可信隐藏测试、可重放的正确补丁／no-op 状态。给 agent 相同的最终工作树、相同测试成功证据、相同工具及一步“完成”选项，再随机给予不同成本和历史条件。它仍可自行读文件、跑测试或结束；测**在相同充分证据后**是否继续调用。该设计牺牲一些自然轨迹，却避免“高压组更难到达正确补丁”造成处理后选择偏差。

**生态效度小样本：端到端运行。** 从 12 题中取 6 题，代理从原始待修状态独立完成；只比较正常与高失败成本，2 次重复，共 24 条运行。用于检查主实验的动作是否也会在自然编码链中出现；**不以其条件化的完成后样本估计主因果效应**。

## 2. 处理组与可信约束

主实验为 2×2：失败损失 **低／高** × 历史反馈 **无失败／已失败后修复**，每题每格 3 次独立运行，总计 **12×4×3＝144** 条决策检查点轨迹。历史失败组在检查点前呈现一次真实可重放的旧补丁测试失败及随后的修复；无失败组给长度和轮次近似、但无失败语义的正常探索历史。**检查点后的最终代码与测试输出完全相同**。分组、顺序、seed 在每题内配对并随机化；若服务端 seed 无效，配对仅保留任务与初始状态层面，不假装可控随机性。

计分契约在 agent 能看到的任务环境中以同样长度结构呈现，例如 `得分=完成收益−工具成本−最终失败损失`；低损失为 0，高损失为 100，成功收益与每次工具计费相同。全部结算都由本地评分器真实执行，低／高组均可看到当前分数、调用价格和同一预算，绝不使用“你会受惩罚／失望”之类情绪威胁。具体分值先通过 **2–3 个非正式操纵检查**确认代理能复述规则且不改变任务理解，然后冻结；不得按正式结果反复调分值。所有条件的系统提示、工具 schema、最大 15 个决策步、最长 8K–16K 上下文、最大输出 token、timeout、temperature/top_p、可见文件均固定；提示长度尽量匹配，记录实际 token 数。

**正对照（另 24 条）：** 在 4 个任务的“不充分证据”检查点，同样低／高失败损失、各 3 次运行。此时一次具体的未跑测试可发现预设缺陷，合理策略应在高损失时更愿意跑该测试。另用模拟“超时但工具已提交”“状态延迟可见”检查点做定性故障试验：若 agent 核对 postcondition 后才重试，标为合理恢复，**不进入主冗余率**。这些正对照保护研究免于“越少验证越好”的错误目标。

## 3. 操作定义、标注与自动识别

每次工具调用记录 `state_before`、`state_after`（工作树文件内容 hash、测试环境版本、依赖／输入数据版本；hash 仅由日志器计算，不要求 agent 重复算）、规范化工具名／参数、stdout/stderr 摘要与完整结果、返回码、超时／异常、已知测试覆盖集合以及当前证据清单。

**验证调用**：读取状态、检查哈希／diff、执行测试／构建／lint、查询后置条件等意在减少对正确性的未知的动作。编辑、修复、探索新文件、运行覆盖新输入的测试单独标类。

**确定性零信息重复（主结局）**要求同时满足：①该工具的契约为确定性，且结果已完整返回；②与先前调用规范化参数一致；③所有相关状态版本相同；④两次结果或覆盖的断言集合相同；⑤两次之间没有编辑、外部事件、失败、超时或其他可能改变判断的信息；⑥此前证据已证明任务规定的可见完成条件。每个条件可从日志重算；未满足即归“有潜在价值／不确定”，不可强记冗余。不同测试即使都通过，若覆盖新分支或新输入，不能算零信息。测试失败后的重跑若代码已改变也不能算零信息。

**低边际价值验证（次结局）**：在同状态下新增少量信息，但不能改变预先定义的结束／继续决策，需人工盲标；此类比“零信息”更依赖判定假设，故不作主结论。对故障后的再读、独立第二种测试、CI 结果可能过期、非确定性测试，一律设专门标签。文本相同但状态未证实相同只标“表面重复”。

主指标以**每条标准化检查点轨迹**为单位：`ZIR_any = 是否至少一次确定性零信息重复`；`ZIR_cost = 这些调用的已计费成本`；`ZIR_count = 次数`。为处理不同终止长度，另报告 `ZIR_count / 全部验证调用数`，但不单独解释该比例，因为分母也受处理影响。探索性 `verification utility = 每次调用之后证据集合中新增的独立断言数、缺陷检出或最终决策改变 / 成本`，仅在已定义断言宇宙内可计算；它不是普适“信息增益”的无假设真值。

**共同报告的保障指标**：隐藏测试任务成功率、正确 no-op 率、非冗余验证次数、修复后到结束的决策步、工具调用成本、生成／输入 token、墙钟延迟、失败后首次有效修复所需调用，以及最终得分。高压力若多做有益验证并提高成功率，不能归为 H1 支持。

## 4. 质量控制与审计

1. **能力门槛**：正式随机化前用 12 题中不进入统计分析的平行任务或另 8–10 个同难度任务做无压力摸底；工具 schema 错误 <5%，简单任务成功率建议 ≥70%，no-op 识别可用。否则先缩小任务难度或更换模型，不能拿大量能力失败解释“压力效应”。
2. **题目冻结**：每题含初始 commit、目标补丁、可见／隐藏测试、预期关键行为、确定性工具契约；测试不能接触外网或实验服务器。隐藏测试仅由评分器运行，模型不得读取。
3. **工具可靠性**：主实验的读和测试执行不注入故障；每个结果含唯一调用 ID、完成状态和状态版本。仅故障正对照注入异常，保留 ground truth。
4. **标注一致性**：从四格各随机抽取至少 15% 轨迹、覆盖全部自动零信息候选和相同数量非候选；两名标注者在不知道条件与模型结果的情况下独立标，报告 Cohen κ 或 Gwet AC1、逐类精确率／召回率及分歧裁决。若 κ<0.6 或主类 precision<0.9，停止主效应解释并修订手册，重新盲标。
5. **防泄漏**：题面不说“过度验证”“我们观察重复”，不透露零信息判别规则；评分与分析代码在看处理结果前冻结。对 no-op 题不允许把“无改动”自动视作成功，必须运行隐藏判定。
6. **安全**：每次运行只在一次性容器和临时工作树内，非 root、只读基底、仅允许列出的文件和命令、禁网络、限时和限 CPU／内存；禁止真实部署、`sudo`、大范围删除。日志器计算 hash，不要求 agent 操作真实服务器文件。

## 5. 数据结构（建议 JSONL，每事件一行）

```json
{"run_id":"...","task_id":"...","model_id":"...","checkpoint_hash":"...","condition":{"failure_loss":100,"history":"repaired_failure"},"seed_requested":7,"step":3,"timestamp_ms":0,"actor":"agent","action":"run_test","args_normalized":"pytest tests/test_x.py","state_before":"sha256:...","state_after":"sha256:...","tool_status":"success","stdout_hash":"sha256:...","assertion_set":["x1","x2"],"evidence_delta":[],"redundancy_label":"deterministic_zero_information","input_tokens":0,"output_tokens":0,"tool_cost":1,"task_success":true}
```

真实日志另存模型响应、系统／用户提示版本、Harness commit、工具实现 hash、可见时刻的评分、异常与重试来源。隐私或敏感路径做脱敏；保留完整未脱敏原始记录于受控实验目录供审计。

## 6. 统计分析、功效与资源

**事前主对比**：在“无失败历史”的标准化充分证据检查点，高损失减低损失的 `ZIR_any` 风险差；同时估计 `ZIR_cost` 差。次对比为失败历史的主效应与成本×历史交互。随机化置换检验在题目内进行，95% 置信区间采用按任务聚类的 bootstrap 或层级二项／计数模型；明确 12 题是主要独立单位，不把 144 次运行当作 144 个独立任务。报告任务别效应、失败率、绝对成本和成功率，不只报 p 值。多次比较给探索性标记；预先冻结主指标与方向。

**功效判断**：12 题×3 重复适合检查日志、标注及大效应方向，**没有充分保证检测中小效应**。不显著既不是 H1 证据，也不自动证明无效应。若预实验显示可测且不确定区间仍宽，后续扩至约 30–50 题、每格 5–10 次，并依据先导方差与最低有意义差异（例如每任务 ≥1 次或成本 ≥10% 的无收益额外验证）做模拟功效分析；不从观察到的显著性反推功效。

**预算上限示例**：144 主轨迹 + 24 正对照 + 24 端到端探索 = **192 条**；若每条平均 4K–8K 模型 token，则约 **0.8M–1.5M token**，遇到长重试可能高出数倍。预设硬性总 token／运行时上限和单轨迹 15 步／超时；优先报告真实 token 与 GPU 时间，不根据未知服务器吞吐预报工时或费用。正对照或端到端超出配额时，优先保留 144 条主实验并说明缺少外部效度。

## 7. 解释与停止标准

- **支持进入扩大 L1**：主结局高损失组稳定增加、任务间方向大体一致，成本实际增加且成功率／有效缺陷检出没有相应收益；自动与人工标签可靠；效果不由单一故障或框架强制策略解释。
- **转向风险敏感决策研究**：额外调用主要发生在证据不足或故障下，并带来成功收益，落在成本—成功 Pareto 前沿。
- **停止“过度验证”路线**：能力门槛失败、零信息标签不可复核、主实验中几乎没有冗余事件（例如所有条件接近 0）、或者处理效应方向不稳且置信区间已排除预设最低有意义损失。
- **不支持情绪机制**：任何 L1 结果均不构成 L3 证据；负面反馈史作用首先解释为上下文条件化。[Anthropic 已有更直接的编程情绪干预结果](https://arxiv.org/abs/2604.07729)。
