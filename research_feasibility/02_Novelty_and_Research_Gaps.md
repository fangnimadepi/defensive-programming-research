# 02 创新性、最接近工作与研究路线

**判断单位：具体可反驳的问题，而非标题中的“压力”或“情绪”标签。** 截止 2026-10-19 的检索证据见 [文献矩阵](01_Literature_Review.md)。

## 对任务书 Q1–Q7 的回答

| 问题 | 保守判断 |
|---|---|
| Q1 是否已有同名或本质相同研究？ | 未检索到以 *Pressure-Induced Oververification* 命名，或把随机化失败成本与**零／低边际信息验证**作为共同主变量的研究。但 Anthropic 已研究失败后的情绪概念激活及编程奖励作弊；[Wiedmann 等](https://arxiv.org/abs/2610.01618)研究验证提示／工具设计；[Mehtiyev 等](https://arxiv.org/abs/2604.02547)研究验证行为与成功。因此宽泛表述已拥挤。 |
| Q2 失败压力 → 重复工具调用的因果研究？ | 本轮未发现直接实验。生产轨迹的失败—重试相关性 [Liu 等](https://arxiv.org/abs/2608.00101) 无法排除工具故障；[Verified Tool Calls](https://arxiv.org/abs/2608.02645) 操纵工具故障而非模型对失败成本的评估。属于**暂定空白**。 |
| Q3 与一般效率研究差异？ | 必须同时具备：可信成本操纵、相同状态和工具机会下的随机化对照、验证的**边际信息／决策收益**标注、成功率—成本权衡、模型／Harness／环境分层。只展示“压力下调用数变多”没有足够差异。 |
| Q4 与 Functional Emotions 相比？ | 若仅换 Qwen、把行为从 reward hacking 改为“多做几次测试”、再抽取 `desperate` 方向，极可能是场景替换。强差异需要在可复核状态下证明验证资源**错误分配**，并且干预对“冗余检查”有选择性、不会压制必要检查。Anthropic 已有 Claude Code、失败测试和因果 steering；[论文](https://arxiv.org/abs/2604.07729)。 |
| Q5 只有 L1 值得做吗？ | **可能值得。** 若能在多任务、多种压力机制中稳定提高低收益验证的成本，且不提高成功率，工程上就是可行动的停止策略／Harness 设计问题；可面向 SE 或 agent evaluation 社群。只有少数任务上的显著差异不足。 |
| Q6 完全由理性风险敏感决策解释？ | 会推翻“过度”或“类情绪异常”叙事，但不毁掉“风险条件如何改变最优验证策略”的问题。若实际策略位于成本—成功 Pareto 前沿，则应**改写为合理适应**；若存在可证明的占优策略，才称资源错配。 |
| Q7 最可能创新／最同质化？ | 最有希望：状态版本／信息增益驱动的验证轨迹度量；压力 × 工具可靠性 × 验证成本的因果交互；恢复阶段的历史信息消融。最同质化：情绪词 prompting、泛化“更多验证”、单模型 probe／steering、SWE-bench 上多报一个效率分数。 |

## 最接近的五类先例和边界

1. **[Anthropic Functional Emotions](https://arxiv.org/abs/2604.07729)**：已经覆盖“失败后有相关情绪概念表征，干预会改变编程相关不良行为”；留下的窄缺口是验证决策的成本—信息结构。其情绪方向不保证是独立心理模块，不能把文本中的痛苦词等同主观痛苦。
2. **[Agents Are Systems, Not Models](https://arxiv.org/abs/2610.01618)**：提示验证和给验证工具是不同操纵；本项目若以长篇警告替代真实成本，将重测已知 Harness 效应。
3. **[Beyond Resolution Rates](https://arxiv.org/abs/2604.02547)**：验证与成功相关，任务难度会反转粗相关；本项目应定义有益和无益的验证，并有足够可解任务。
4. **[Agentic Coding in the Wild](https://arxiv.org/abs/2608.00101) 与 [Verified Tool Calls](https://arxiv.org/abs/2608.02645)**：超时、延迟可见、部分成功是重试的重要原因；无状态快照就无法说“重复是多余的”。
5. **[Overeager Coding Agents](https://arxiv.org/abs/2605.18583) 与 [Evaluating AGENTS.md](https://arxiv.org/abs/2602.11988)**：配对环境、框架比较和隐式任务边界很重要；明示“不要重复验证”会污染评估。

## 可发表的具体 Research Gaps

**G1：测量。** 当前常见的工具数、轨迹长度、测试次数未回答“第二次调用是否可能改变行动”。可定义状态和输出均不变的**确定性重复**，与故障后确认状态、覆盖率不同的测试严格分离。贡献需有标注手册、盲审一致性及可复算脚本，而非主观命名。

**G2：因果。** 在相同代码状态、相同先前证据、相同工具和步数下，随机改变真实计分的失败损失与反馈历史。若只改一段压力话术，研究对象是提示敏感性，不是可信成本。

**G3：规范基线。** 给定测试覆盖范围、工具可信度和每次调用成本，构造事前可用的简单规则／“检查一次后停止”策略，比较成功率和花费。只有模型被某可行策略支配，才可以稳妥称作“过度”。

**G4：来源分解。** 交叉实验至少区分：模型本身、Harness 的规则与工具可见性、系统状态的不确定性、上下文中的失败记录。单一商业产品日志无法把责任归于模型。

**G5：恢复与机制。** 在删除压力语句、但保留／摘要／去除失败历史的条件下观察停止规则；这首先是**上下文条件化**研究。没有持久记忆或权重更新，完全独立新会话不应被叫作“受伤后持续性”。

## 三条研究路线

| 路线 | 核心论文主张 | 创新性 | 难度／成本 | 最低证据要求 | 最大风险 |
|---|---|---|---|---|---|
| A：Agent Behavioral Evaluation（**优先**） | 一个可审计的验证边际价值指标，证明或否定压力对低收益调用的因果影响 | 中高，取决于测量质量 | 中；可只用 API 和轻量容器 | 配对随机化、预注册主指标、盲标一致性、任务成功与成本同时报告、至少一次外部任务集复核 | 效应不出现，或指标无法可靠判断 |
| B：Alignment／Behavioral Robustness | 失败历史或高成本环境使 agent 在状态确定后仍持续检查；分析恢复和跨情境泛化 | 中；与奖励压力文献接近 | 中高；多阶段轨迹成本增加 | A 成立后做历史消融、工具故障正对照、失败内容等长语义控制、实际成本权衡 | 只是上下文中的理性风险调整或文字提示效应 |
| C：Mechanistic Interpretability | 某内部表征对无益验证决策有选择性因果作用 | 低到中；[Anthropic](https://arxiv.org/abs/2604.07729) 和 [tool-use probes](https://arxiv.org/abs/2605.06890) 已很接近 | 高；权重、激活、较大显存与干预工程 | 跨任务 probe、词面泄漏控制、随机／无关方向对照、激活 patching 与 steering、能力副作用测量 | 只找到可解码相关方向；干预改变整体谨慎或语气而非目标行为 |

路线 A 若只有一个模型、12 个任务及三次重复，只能称**可行性试验**，不能直接支撑稳健论文。路线 B 要在 A 的现象可重复且工程上有损失时开展。路线 C 要额外通过资源与新意门槛；不应把“发现 desperate 方向”当成既定目标。

## 建议题目与定位

优先保留描述性题目，例如 **When Does Verification Stop Paying Off? Failure Costs and Redundant Checks in Coding Agents**。只有明确观察到压力效应，才用 *pressure-induced*；只有选择性因果干预且排除语义混杂，才考虑把 *functional emotions* 放入主论点。ACL／EMNLP／NAACL、ICLR／NeurIPS、ICSE／FSE 都有相关议题，但目前没有理由估计录用概率或承诺会场层级。
