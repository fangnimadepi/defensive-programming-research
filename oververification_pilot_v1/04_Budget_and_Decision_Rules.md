# 04｜资源预算、阶段门槛与止损规则

日期：2026-10-27。可用资源：两块 A100、RTX 3060 Laptop、可报销 DeepSeek 官方 API；A100 显存/占用时段未知。以下是规划算术，**不是实测吞吐或项目报价**。

## 1. 资源分工

| 资源 | 第一版用途 | 何时才扩大 |
|---|---|---|
| 笔记本 | 有限域枚举、执行器、任务生成、日志审计、统计；这些工作主要用 CPU | 本地小模型仅做格式烟测，不替代正式能力检查 |
| 第一块 A100 | 一款开放权重模型推理 | P0 证明该模型能完成任务后才跑 E1 |
| 第二块 A100 | 可选并行运行或更大模型诊断 | 不要求两卡同时占满；先确认显存与可用时段 |
| DeepSeek API | 另一模型行为对照 | 精确版本和模式冻结；Flash/Pro 不计为两个独立家族 |
| 学校超算 | 本轮无需 | 已有稳定效应后，用于更多任务、家族或更大模型，须回答明确缺口 |

7B/14B 的 BF16 裸权重约 14/28GB，只是 `参数量×2 bytes` 的算术。真实部署还需 KV cache、框架缓冲、并发与上下文空间；14B 在 40GB 卡上的余量不可凭裸权重保证。先选现成可用且通过 P0 的模型，不因论文趋势下载大型权重。

## 2. 分阶段规模：不能把两种研究都塞进 384 条

| 阶段 | 计算 | 轨迹数 | 一半走 API 时 |
|---|---|---:|---:|
| P0 | 8 开发任务 × 4 分支 × 2 模型 | 64 | 32 |
| E1 | 24 任务 × 4 信息/损失条件 × 2 模型 × 2 重复 | 384 | 192 |
| E2 | 24 任务 × 2 损失 × 4 分支 × 2 模型 | 384 | 192 |
| 合计 | 以上相加 | **832** | **416** |

另加每模型 12 次单轮规则/能力诊断，共 24 次，不混作 24 条多步轨迹。P0 的复查分支约需 112 次模型调用，加诊断约 136 次；E1 每轨迹最多 9 次调用，E2 每轨迹平均 1.75 次。于是无重试上界式计数约 `112 + 24 + 384×9 + 384×1.75 = 4,264` 次调用。真实 E1 常会提前停止；服务端额外调用和重试必须另记。

初筛不是必须一次完成：**最小投入为 P0；E1 用于行为筛查；E2 用于价值分解。** 若 E1 没有预设问题的信号且测量有效，不能为了完成预算机械地把后续实验全跑完。

## 3. API 预算：现金很可能不是瓶颈

2026-10-27 核对 [DeepSeek 官方价格](https://api-docs.deepseek.com/quick_start/pricing/)：峰时、缓存未命中、每百万 token，Flash 输入 $0.30 / 输出 $1.20，V4 Pro 输入 $1.32 / 输出 $3.96。页面所列版本分别为 DeepSeek-V4.1-Flash-1017 与 DeepSeek-V4-Pro-0813；实际运行前重新检查别名和价格。此处不预支非峰时或缓存折扣。

统一取**每轨迹累计输入 32k、累计输出 4k**作比较预算，包含多轮重复输入；这不是单条 prompt 长度。E2 较短，可能远低于该数；thinking、重试或长代码也可能超出。

`费用 = 总输入tokens/1e6 × 输入单价 + 总输出tokens/1e6 × 输出单价`。

| 范围 | 全部走 Flash | 全部走 Pro | 一半本地、一半 Flash | 一半本地、一半 Pro |
|---|---:|---:|---:|---:|
| P0 64 条 | $0.92 | $3.72 | $0.46 | $1.86 |
| E1 或 E2 384 条 | $5.53 | $22.30 | $2.76 | $11.15 |
| 全部 832 条 | $11.98 | $48.32 | **$5.99** | **$24.16** |

这些列是替代方案，不是需要全部累加。单轮诊断、失败请求计费、额外模型、thinking 输出和裁判费用未包含；主试不用 LLM judge。缓存计费折扣只影响现金，不改变检查是否有价值的实验标签。

可把“单一本地模型＋单一 API 模型”的现金预留设为上述 token 估计的 3 倍：Flash 路线约 $18、Pro 路线约 $73，作为监控线而非消费承诺。P0 实测后应重新计算，并在批量开始前设硬上限。若费用异常，检查上下文重复、输出截断重试和适配器，不自动升级模型。

## 4. GPU 时间：条件估计，而非硬件承诺

沿用此前预算符号，示例输入 I=32k、输出 O=4k，prefill 折算系数 α=0.1、非理想开销 f=1.5：

`H = N_local × (O + αI) / (3600q) × f`。

q 是本地实际配置的有效 token-equivalent/s/GPU。仅以 **20–80** 为规划区间，不声称已经测到；按 7–14B、短上下文、合理 batching 的未知配置做敏感性占位。

| 范围 | 本地轨迹 | 规划 GPU 小时 |
|---|---:|---:|
| P0 | 32 | 1.2–4.8 |
| E1 | 192 | 7.2–28.8 |
| E2 | 192 | 7.2–28.8 |
| 全部 | 416 | **15.6–62.4** |

小型 E2 真实消耗可能低于统一假设；模型服务、单请求小 batch 和排队也可能更慢。GPU 小时是卡数×运行小时，两卡并行缩短墙钟时间不等于 GPU 小时自动减半。学校共享排队时间不含在表内。

最可靠的预算步骤是 P0 记录各分支累计 token、prefill/decode、工具 CPU 秒和端到端时间，用 p50/p90 分别给主预算与余量。未实测前，不承诺“一晚上跑完”。

## 5. 人力与工程范围

一人使用已有 Python 与模型接口经验的粗规划：

| 工作 | 集中工作量估计 | 验收依据 |
|---|---:|---|
| 四任务族、独立真值、S/N 与缓存 | 3–5 人日 | 正确/缺陷候选及过期证据检查通过 |
| 最小模型适配、日志与 P0 | 2–3 人日 | 请求可重建，成本完整，能力门槛明确 |
| E1/E2 分批运行与审计 | 2–4 人日 | 分配完整，无静默缺失或成功样本筛选 |
| 统计与决策报告 | 1–2 人日 | 配对效果、区间、失败解释、继续/停止结论 |

合计约 **8–14 人日**，不含硬件排队、接口排障或复杂部署。若工作量超出，优先减少框架包装和附加因子，保留独立真值与核心对照；不要先删除回放/内部复查对照来凑出便宜但不可解释的结果。

## 6. 阶段决策表

| 阶段结果 | 决策 | 下一动作 |
|---|---|---|
| G/缓存/隔离任一不可靠 | HOLD | 修复测量，暂停模型采样 |
| P0 模型不会修复、听不懂积分，或所有臂都近满分 | REVISE ONCE | 简化/调整开发任务或换能力合适的模型；保存修订，不看正式集调参 |
| 修订后仍无可解释测量 | NO-GO 当前设计 | 停止扩样，不能用更多 tokens 弥补 |
| P0 通过，E1 存在可解释的信息响应或旧测试重执行 | GO E2 | 做价值分解，不能先称“过验证” |
| E1 旧测试几乎从不重执行，且信息/积分理解正常 | STOP 压力路线初筛 | 记录受控设置未发现现象；最多做预定自然轨迹迁移检查 |
| E2 显示旧证据回放/内部复查有明显收益 | PIVOT 解释 | 研究低成本认知辅助；撤回“旧信息必然无用” |
| E2 新测试没有被有效利用 | REVISE 测量 | 区分候选太易、测试无诊断性、修复能力不足；不能解释为所有验证无用 |
| 有一致的大效应，但区间仍宽 | GO 确认设计 | 增加独立任务结构，按先导方差与经济阈值计算样本量 |
| 只有缓存节省执行时间，模型质量/token 不变 | 工程结果，论文新意弱 | 作为 baseline 或系统改进，避免加机制分析包装 |
| 只有一次重复/单一任务族驱动 | 不扩大机制投入 | 优先独立任务验证或止损 |

“大效应”是初筛优先级判断，不是 p 值门槛：预先关注旧测试首次重执行率约 15pp 以上差异，或某一继续分支约 10pp 以上质量变化；同时要求不是仅一个任务族/异常轨迹驱动。数值只是值得继续审查的资源分配阈值。低于阈值不证明效应不存在，零事件也不提供跨任务族的安全保证。

## 7. 何时值得申请更多算力

优先顺序是：新增机制不同的任务 → 独立模型家族 → 原始缺陷起点的自然修复轨迹 → 更长上下文/过期证据 → 必要时训练或激活研究。

若要把初筛升级为论文，至少补上两项：

- 在未用于调整协议的新任务结构上，确认“损失—选择—真实收益”的关系；给出围绕经济阈值的足够精度，而非只报告不显著。
- 在自然编码轨迹的预定重复意图处做随机干预，验证标准化检查点结论是否迁移，并测量误停止/误用缓存的代价。

只要问题仍是黑盒决策和确定性小任务，更多数据优先于更大模型与 RL。是否申请超算应由确认阶段的实际样本量或模型内存缺口决定。

## 8. 初筛之后应能回答的三个问题

1. 模型在确定的旧证据面前，是否仍愿意付费重执行，而且该倾向是否随失败损失变化？
2. 有用的部分来自新测试、旧结果重呈现，还是额外计算；哪些结论仍因样本不足而未知？
3. 下一笔资源应投入更多任务确认、缓存/证据管理改进，还是停止这条路线？

如果这三问仍因测量设计含糊而答不出，扩到更大模型不会自动解决问题。
