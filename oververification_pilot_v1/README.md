# 重复验证何时值得做：初期实验方案 v1

日期：2026-10-27。状态：**深入调研与待实施设计，尚未运行模型实验**。承接 [低成本方案 A](../research_feasibility_v2/09_Low_Cost_Research_Options.md)。

## 本次判断

**CONDITIONAL GO：值得先做一个有明确止损点的诊断实验。** 新检索发现，编码 agent 的验证成本、贝叶斯停止、反事实信息充分性和重复操作治理已有直接工作；上一轮对“边际验证价值”的创新空间估计需要收紧。单纯展示“少调用几次、正确率没有显著下降”已经不够。

目前较值得验证的问题是：**当旧证据仍有效、且可低成本重看时，失败损失会不会推动 agent 支付更高成本重新执行检查？这种选择能否由真实质量收益解释？** 必须同时允许另一种结果：重复确实帮助模型理解证据，或高失败代价下小幅质量提升已经足够划算。

## 建议如何启动

| 阶段 | 做什么 | 规模 | 决策用途 |
|---|---|---:|---|
| P0 | 检查任务真值、模型基本能力、新证据是否可利用、缓存是否正确 | 64 条短续跑；另 24 次单轮诊断 | 只决定环境是否可用 |
| E1 | 自主选择：失败损失低/高 × 检查旧/新测试 | 384 条 | 判断选择是否对信息与损失敏感 |
| E2 | 同一快照分叉：直接提交、内部复查、旧证据回放、新测试 | 384 条 | 估计额外计算、证据重呈现、新观察的收益 |

完整初筛共 **832 条短轨迹，外加 24 次单轮诊断**；逐阶段推进，不一次性跑完。最省钱的第一步只是 P0。E1 的 384 条不能同时承担行为测量和全部因果对照，因而本版明确另列 E2 成本。

首选一款现有、通过能力检查的 7–14B 开放模型，加一个 DeepSeek 官方 API 模型。A100 用于推理，笔记本负责小任务执行与统计；目前无需训练、激活分析或申请超算。以每轨迹累计输入 32k、输出 4k 的示例估计，若一半走 API，832 条的 API token 费用约 Flash **$5.99** 或 Pro **$24.16**，不含诊断、重试和超长输出。成本假设及 GPU 时估计见 [预算](04_Budget_and_Decision_Rules.md)。
